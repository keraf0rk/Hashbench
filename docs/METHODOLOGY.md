# Методология экспериментов

Стенд воспроизводит два теста из журнала «Хакер» и сравнивает результат с эталоном (Apple M4).

## Исходные данные

Оба эксперимента используют два заведомо известных пароля:

- `Qwerty12!`
- `123password456`

Скрипт хеширует их сам (а не переписывает хеши с картинки) — так исключены опечатки. Контрольные значения для сверки с журналом:

| Пароль | SHA-256 (начало) | sha256crypt (соль `xyz`, 5000 раундов) |
|--------|------------------|----------------------------------------|
| `Qwerty12!` | `b188cb9b...` | `$5$xyz$DmIBRKf.qMEljFGT8FQrqpt6Mra4c5wFwTn9NCPtUw0` |
| `123password456` | `389137315...` | `$5$xyz$/wEC.Xgv1YSgEBCi.tkRwQ1gHu85bHqsiKkioKTby0D` |

Скрипт печатает `[OK]`, если первый хеш совпал с журнальным. Если `[!]` — данные неверны, дальше мерить нет смысла.

> **Критично:** хеш считается от пароля **без завершающего перевода строки**. В bash — `printf '%s'` (не `echo` без `-n`), в PowerShell — кодирование строки в ASCII-байты напрямую. Один лишний `\n` — и хеш не совпадёт.

## Эксперимент 1 — бенчмарк vs реальная атака

**Вопрос:** насколько `hashcat -b` (бенчмарк) отражает скорость настоящей атаки?

**SHA-256 (режим 1400).** Хеш быстрый, и всего 2 цели. Если гнать прямой словарь, GPU простаивает (ему нечем занять тысячи ядер) — именно так журнал получил расхождение в 1000×. Чтобы замерить **честную** скорость, мы грузим GPU маской `?a?a?a?a?a?a?a?a` (8 произвольных символов): кандидаты генерируются прямо на GPU миллиардами, ядра загружены. `--runtime=30` останавливает через 30 сек (пароль маской не найдётся, нам нужна только скорость).

**sha256crypt (режим 7400).** Хеш медленный (5000 итераций), GPU не голодает даже на словаре — поэтому реальную атаку гоним словарём `rockyou.txt` + наши пароли.

Для каждого режима сравниваем `Speed.#` реальной атаки со `Speed.#` бенчмарка. Отношение = во сколько бенчмарк завышает.

### Почему `--potfile-disable` обязателен

hashcat кеширует взломанные хеши в potfile. Без `--potfile-disable` второй запуск увидел бы «уже взломано» и не стал бы мерить скорость. Флаг заставляет каждый прогон считать честно.

### Как читать результат

- **Расхождение ~1.2–1.3×** (как на M4) — бенчмарк близок к реальности. Типично для unified-memory (Apple Silicon).
- **Расхождение в разы** — нормально для дискретных GPU: данные ходят по PCIe, на быстрых хешах GPU голодает.
- **Расхождение в сотни-тысячи раз** — почти всегда признак плохо поставленной атаки (мало хешей + прямой словарь), а не свойство железа.

## Эксперимент 2 — стабильность бенчмарка

**Вопрос:** даёт ли `hashcat -b` одинаковый результат при повторах?

Пять прогонов `hashcat -b -m 1400` подряд, смотрим разброс.

- **Малый разброс** (M4: 0.03%) — предсказуемо; характерно для пассивного охлаждения без динамического разгона частот за короткие прогоны.
- **Большой разброс** — ожидаем на игровых дискретных картах: boost-частоты и прогрев кристалла гуляют от запуска к запуску.

## Ограничения

- Абсолютные цифры зависят от версии hashcat, драйвера и теплового режима. Сравнивать стоит **отношения и порядки величин**, а не последние знаки.
- `rockyou.txt` берётся из публичного зеркала; содержимое может отличаться между копиями. Наши два пароля дописываются в конец, чтобы крек был детерминирован.
- Для memory-hard (scrypt/Argon2) на машинах с малым объёмом выделяемой GPU-памяти бенчмарк может не запуститься вовсе — это тоже результат (см. `docs/ALGORITHMS.md`).
